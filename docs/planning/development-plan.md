# NexaSM 开发执行计划

日期：2026-10-29。状态：待实施计划，不是完成报告。
依据：[SM-DESIGN-001 v0.1](NexaSM_Development_Design_v0.1.md)。附件是设计输入，其中的示例、外部引用和建议不视为已经验证的实现事实。

## 1. 范围、现状与交付边界

目前 NexaSM、NexaAC 均只有说明文档与目录占位，无工程、测试、CI 或可执行程序。本轮交付开发计划，不安装运行时、不实现产品、不创建远程工单。

第一目标：Standard 本地单机真实闭环——创建/导入、固定版本安装、启动、可信状态、控制台、停止、退出 UI 后持续运行。第二目标：完成可恢复备份和恢复后再形成可用于真实持久世界的候选版本。M2 是受限桌面 Alpha，M3 才是包含数据安全闭环的候选；M2 不宣传已有完整备份保障。

保持 Node/Controller/Standard 共用实现；AC 独立交付，SM 不进入游戏热路径。Web、多节点、Fleet、HA 不阻塞首条单机链路。首期不开发内核反作弊、通用云计费、透明世界分片或跨地域多主。

## 2. 决策和阻塞项

| 项目 | 当前地位 | 执行安排及出口 |
|---|---|---|
| XSR、独立产品、三种组合、关闭 UI 不停服 | 已确定方向 | 通过引用门禁和生命周期测试固化 |
| .NET 10、SQLite、进程独立 Supervisor | 设计建议 | M0 原型后以 ADR 记录版本、限制和选择理由 |
| PostgreSQL、远程二进制传输、HA | 后续建议 | 分别在 M4/M6 决策，不提前增加依赖 |
| XSR/Platform/Renderer 发布包 | XSR 核心共享包与 SM Composition 已实现，源码/包哈希固定 | 按 [上游检查](../verification/nexacl-xsr-inspection.md) 继续发布源配置与跨平台验收；Platform/Renderer 分别验收，禁止跨仓库源码引用 |
| NXML/NSS 和渲染器能力 | 附件引用，未审计 | M0 最小消费原型；缺包时可继续纯领域/TestProcess，不能宣称桌面就绪 |
| 首发平台 | 本计划暂选 Linux x64 工程验证 + Windows x64 桌面验证 | M0 登记可用执行器；Windows 服务、UI 必须 Windows 实机/runner 验证；ARM64/macOS 另列矩阵，不外推 |
| Provider 首组 | 暂选 Vanilla 单一固定稳定版本，然后 Paper 单一固定构建 | M0/M2 核实官方元数据、Java 和许可，记录精确版本与摘要，不填 latest |
| 附件 schemas/examples | 未随本次上传提供 | M0 按模型补齐并评审；不把附件对配套文件的提及当成文件已存在 |

未知包版本不凭空编造；缺外部包仅阻塞其消费者。建议采用与目标 .NET 兼容的测试框架并在 M0 锁定版本；持久化与 IPC 各先验证一个简单候选，失败再比较替代。所有 ADR 保留 Proposed/Accepted/Superseded 状态。

## 3. 依赖与阶段出口

关键链：SM-001 → SM-002 → SM-003/004 → SM-005 → SM-006 → SM-007 → SM-010 → SM-011/012。
SM-008/009 可在资源契约稳定后推进，与进程链在 SM-010 汇合。SM-013 不应拖延本地 Alpha。完整任务见 [backlog.md](backlog.md)。

| 阶段 | 可演示交付 | 出口证据 | 不包含 |
|---|---|---|---|
| M0 架构基线 | 最小工程、资源/Operation 模型、TestProcess、引用门禁 | 干净 checkout 可构建测试；依赖锁；包消费和 AOT 原型记录 | 空工程堆砌、完整平台承诺 |
| M1 执行闭环 | CLI 控制 TestProcess；持久启动、停止、重连对账 | T-001–010；补 T-011/012/017/018/032 的本机部分；真实服务安装生命周期 | 真实 Minecraft 与桌面完成声明 |
| M2 桌面 Alpha | Standard OOBE、创建/只读扫描导入、Vanilla/Paper、操作中心和控制台 | 固定 Provider 实际启动停止；UI 退出不影响 Run；T-020/021/034/035；发行物冒烟 | 多节点、全加载器、在线一致性备份 |
| M3 数据安全 | 配置漂移、停服备份、恢复、内容暂存更新、计划任务 | T-008/022–024/028/031；真实世界恢复演练、原数据保留 | 未验证的热备份保证 |
| M4 远程/Web | 配对、鉴权、订阅、远程 Node、Web、控制权转移 | 3–5 个真实节点；T-017–019/025/029/033；真实升级与分区 | HA 或 Hypixel 规模宣称 |
| M5 网络/Fleet | 放置、预留、代理路由、Sessions、排空灰度 | T-013–016/026/027；实际小游戏桥接和分区测试 | 透明 TCP 会话迁移 |
| M6 生产加强 | 明确范围 HA、升级恢复、规模/长测、发行证据 | 目标规模硬件报告、24h/72h 实测、支持矩阵、安全评审 | 从模拟会话数推断 JVM 容量 |

T-030 是各阶段交付可执行目标的持续门禁，逐步增加运行路径；不能等到 M6 才测试 AOT。每阶段保留失败、跳过、未运行三种结果，不以零测试判绿。

## 4. 首三轮迭代安排

以验收完成度组织迭代，不在团队人数、共享包可用性、平台资源未知时承诺日期。每轮结束记录实际工时、返工和阻塞，再估算下一轮；并行工作需明确模块负责人和契约版本。

### 迭代 A：能构建、能测试、能持久接受

1. 登记现有仓库与包供应情况，完成 ADR-001/002/003 的实现依赖图。
2. 锁定 SDK、包源和依赖；建立最小 Domain、Contracts、Services、组合入口及必要测试工程。
3. 实现强类型身份、版本维度、正交状态、错误和命令封套；确认序列化未知字段/大小限制。
4. 验证 SQLite 事务与 AOT，完成 Operation、幂等和 Outbox 最小持久切片。
5. TestProcess 支持慢启动、超长输出、拒绝停止与受控退出；每种模式可确定性复现。
6. 演示同 key 同 payload 返回相同 Operation，不同 payload 冲突；重启宿主后记录仍在。

出口：工程可从干净环境还原；契约与数据库并发测试实际执行；共享包缺口有准确阻塞范围。此时尚不能宣称 JVM 启停完成。

### 迭代 B：不双启、不误杀、可恢复

1. 平台后端定义 argv、环境、身份、句柄、退出与 IO 边界。
2. Supervisor 独立宿主、本地认证、启动账本、受限控制命令。
3. 在 spawn 与回执提交各边界注入崩溃，验证核实/NeedsAttention 分流。
4. NodeLifecycle 与 Reconciler 共用唯一执行路径；意图版本阻止旧 Start 覆盖 Stop。
5. 加入独占卷最小互斥、maintenance 门禁；完整备份后置，但启动安全不能后置。
6. CLI start/stop/observe/operation，稳定机器可读输出和退出码；原始 console 默认不重放。

出口：M1 用例通过；节点重启时存活 Supervisor 保管 Run；监管崩溃确实丢通道时明确报告。平台服务模式与终端运行分别取证。

### 迭代 C：真实服务端与 Standard

1. 固定 Provider/Java 版本与来源；下载验证、只读导入扫描、隔离暂存和提交。
2. 用真实服务端验证参数文件、就绪、优雅停止、端口冲突；条款由用户明确接受。
3. Standard 组合根复用既有服务；Presentation 投影 Operation 和权威状态，NXML 页面只输出意图。
4. OOBE、服务器列表、实例详情、受限控制台、操作中心；关闭/重开 UI 重新拉取状态。
5. 发布首个受限 Alpha 候选，记录不支持的平台、Provider 和恢复能力；随后进入 M3。

## 5. 工程与分支组织

现有 src/contracts、services、node 等是说明占位，不是程序集。M0 按设计第 28 节逐步引入 NexaSM.Domain、Contracts、Services 等实际项目，并更新旧占位链接；无需一次建立全部未来项目。

main 为经验证基线，develop 为集成；现有 feature/node、feature/controller、feature/standard 是方向分支，不作为独立发行代码库。具体任务采用 feature/sm-003-operations 等短期分支，从 develop 分出，PR 回 develop，避免依赖未合并的跨分支文件。共享契约先合并，再消费。发布用 tag 与发行 manifest 区分角色和 RID。

一次 PR 尽量是一条可验证切片：契约、领域/服务、持久化、注册、消费者、失败路径、测试和文档。原型例外需明确“验证结论而非产品能力”，不可把空接口视为业务交付。

## 6. 测试、CI 和证据

见 [verification-plan.md](verification-plan.md)。PR 先执行构建、领域/契约、依赖门禁和相关进程集成；平台发行执行 AOT/trim 后真实运行。Provider 下载/真实世界及平台安装测试由具备权限的 runner 执行；定时长测保留原始输出。没有平台 runner 时标未验证，不能用 Linux 结果证明 Windows Job 行为。

预算先照设计第 24 节作为可配置起点，记录压力下队列、拒绝、Gap、RSS、恢复时间；不得写成 SLA。命令停止通道要在日志/重连洪峰中保持可处理。重复启动、世界双写、误杀、错误删除、假成功、无界增长均阻止发布。

## 7. NexaAC 协作计划

SM 本轮只建立 ProtectionBinding 和能力适配端口；SO/SC、ClientPolicy、KernelPolicy、EnforcementPreset 属于 AC。双方联合评审版本协商、Run/策略关联、时效、失联与错误语义。Installed/Compatible/PolicyApplied/ProtectionReady 分别投影，不以安装成功代替就绪。

SM-016a 在 M2 用明确标注的测试适配器验证普通 Workload 无 AC 可运行、required 缺失阻止新准入；SM-016b 在 M4 或 AC 真实适配器可用时验证真实回报。测试适配器不计真实保护。AC 驱动、检测和证据内部设计另行立项，不写入 SM 实现。

## 8. 启动前检查与完成定义

- 包/SDK：明确来源、版本、锁和许可；共享包实际消费可验证。
- 平台：Linux 与 Windows 的执行资源、服务安装权限分别登记；不可用项标阻塞。
- 数据：测试工作目录与真实用户世界隔离；故障测试保留原数据、证据和清理步骤。
- Provider：精确软件/Java、授权、摘要与就绪协议矩阵；无摘要标不可用而非伪造验证。
- 范围：确认首轮只做 M0/M1，按上述默认平台推进；后续平台不冒称支持。
- 完成：验收证据与目标提交关联，文档同步，失败路径说明，无遗留发布阻断项。

SM-001 核心工程、共享包消费与持久接受切片已实施；当前证据及剩余出口见 [M0 验证](../verification/m0.md)。
