## 场景与执行资源

- Linux x64：CI 单元/契约、真实进程与文件系统、本地 IPC；systemd 行为必须在真正服务环境测试，容器内假模拟不能替代。
- Windows x64：Job/服务账户/最后句柄语义、文件占用、路径/reparse、桌面、发行物 AOT。云 Linux 执行器不能证明这些结果。
- macOS/ARM64：目标待验证；进入发布支持矩阵前分别补运行证据。
- Provider：固定版本 Vanilla 与 Paper；先验证元数据/Java，再安装/就绪/停止/恢复。Fabric/Forge/NeoForge/Quilt/Velocity 后续逐项增加。
- L0 为单实例真实闭环；L1 为约 10 实例 IO/状态竞争；L2 为 3–5 真实节点；L3 为 1000 模拟节点、10000 资源，仅测控制面。

## 故障注入规则

每个持久事务、spawn、目录切换前后设置可控故障点；重启后验证真实事实与账本，而非只检查异常类型。测试使用隔离临时数据与可核实进程身份。模拟器先保证可复现，再用真实 OS/Provider 复验关键行为。

停止、恢复、删除、迁移都需要负向测试：缺授权、目标版本变化、旧会话、未知进程、仍有写入者时必须拒绝或 NeedsAttention。恢复测试比对原卷与新卷内容，并保留失败现场，不在测试清理阶段掩盖数据损坏。

未运行的平台/Provider 不计支持；跳过用例必须说明原因和影响。24h/72h 长测只有完成并有原始采样才算证据。每个版本记录已通过、失败、跳过、未运行，不以 CI 编译成功代替运行验收。
