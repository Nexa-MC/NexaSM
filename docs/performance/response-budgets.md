# 响应预算（最高优先级）

用户要求：简单操作响应不得超过 10ms，其余操作响应不得超过 100ms。
这是产品验收上限，不能只用平均值、P95 或吞吐率代替。预算不因引入 XSR、插件或 UI 特性放宽。

## 语义

响应指操作入口到首次有效结果/状态，不把游戏下载、备份复制、JVM 启动等任务的完成时间说成 100ms。长操作的持久回执必须在提交后发出；未完成持久接受时返回 AdmissionOutcomeUnknown，使用相同幂等 key 重试，不伪报成功。

当前本地组合采用 80ms 内部接受等待预算，为外层路由/序列化预留 20ms。活动持久任务最多默认 4 个，达到上限立即 AdmissionBusy，没有无界等待队列。超时/取消等待不会释放仍在执行的容量或重复投递。

NexaSM 默认不启动 Sidecar、不等待 SidecarReady，不启用宿主自动补丁插桩。简单本地读只读已有状态，不执行 IPC、持久化或外部查询。

## 当前门禁

`eng/check_response_budget.py` 调用真实 M0Probe，保留每个样本组的最大值和数量：

- 本地状态读取 10000 次：10ms。
- 固定命令解析校验 1000 次：10ms。
- 真实 SQLite 持久接受 100 次：100ms。
- 过载拒绝：10ms。
- 真实 SQLite 写锁竞争下返回结果未确定：100ms；释放锁后验证原操作实际提交。

普通与 Linux x64 AOT 各运行一次，任何组超限都会让检查失败，原始输出保留。测试在启动初始化后进行；启动本身以及未来桌面输入到绘制、远程网络、列表分页等尚无实现/测量，必须在相应里程碑新增端到端场景，不能由当前核心数据代替。

C# 定时器/线程调度不是硬实时系统；80ms 超时设置不是无条件 100ms 保证。验收证据须包含硬件、OS、运行模式、负载与最大观测值。过载、冷路径、GC 和未来 UI 调度均需独立验证；未测量路径不宣称满足预算。

SQLite 写入由一个可复用专用线程串行执行，默认最多 4 个在途请求（执行与排队合计）。使用有界队列，不占用公共线程池等待存储；组合根由后台宿主管理，释放时排空已接受的写入。
