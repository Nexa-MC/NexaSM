## 用例覆盖边界

T-001 仅证明 100 次并发请求产生一个持久 Operation，不证明只有一个活动 Run（尚无进程执行）。T-002/003 覆盖本地事务接受；T-005 仅证明停止意图与重试语义；T-012 用 Outbox 写入失败注入验证事务回滚，不是实际磁盘写满实验。T-004 的 OS spawn 崩溃窗口留待 M1。状态流同步、真实权限系统、监管身份和卷 fencing 均未实现。

FaultHarness 现在覆盖上述五个持久接受窗口：父进程按测试回调标记终止自己创建的探针；新 SQLite 连接执行 journal 恢复并校验意图版本、Operation 和 Outbox 全部一致。另保留触发器注入写失败的事务测试。仍不涵盖断电、文件系统损坏、任意机器指令位置或 OS spawn 窗口。

## 本轮新增与具体修正

- 架构登记路径统一使用 POSIX 形式；补 PureWindowsPath 测试，避免 Windows 反斜杠引发误报。这是跨平台路径逻辑验证，不是 Windows 实机运行。
- ExpectedVersion.Value 必须显式提供且为整数；空对象、null、字符串不再默认为 CAS 版本 0。
- [内部契约](../contracts/desired-state-v1.md) 与两个 JSON 样例已加入；测试实际经过 CommandCodec、OperationService 和 SQLite 消费样例。
- SQLite 连接初始化失败时释放连接；故障检查点仅由内部测试构造参数设置，不向网络或配置开放。
- 旧 PCL-N/refactor/xsr 检查为历史记录；当前已按用户指示检查 Nexa-MC/NexaCL main。独立消费实验与正式共享包发布分开计证据，见新增上游检查记录。
